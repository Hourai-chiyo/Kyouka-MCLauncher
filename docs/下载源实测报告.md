# Minecraft 下载源实测报告

- 测试时间：2026-10-20 16:52（Asia/Shanghai）
- 测试位置：本机（中国大陆网络，系统时间为 2026-10-20）
- 测试方式：curl 直连，只读 GET，大文件写入临时目录后即删
- 背景：PCL / HMCL 已移除 MC 下载功能、鸣潮及各应用商店 MC 入口关闭，故需确认替代下载源

---

## 一、结论（先看这个）

1. **BMCLAPI 没有"受损"到不可用的程度。** 它是「中心调度 + CDN 节点」架构：
   - 中心调度正常（HEAD 返回 200，manifest 完整 277,821 字节）
   - 但 `bmclapi2` 会把请求 302 重定向到节点 `bmclapi21.sakura.sld.tw`，**该节点当前连不上（超时）**
   - **备用域名 `bmclapi.bangbang93.com` 直接 200 正常**
   - 文件层下载实测 **1.6 MB/s**，完全健康
   - 所以：**挂的是节点，不是服务**；节点故障是这类架构的常态，会自愈
2. **Mojang 官方源其实不慢。** 实测 1.36 MB/s（大文件）、243–249 KB/s（manifest）。可作主用源。
3. **真正坏的是 NeoForge 的 maven**：`maven.neoforged.net` 被解析到 `108.160.172.1`（Dropbox 的 IP，明显是 DNS 污染），连接必超时。
4. **概念纠正**：CurseForge / Modrinth **不提供 MC 本体**（没有 client.jar / libraries / assets），只提供 Mod、整合包、资源包、光影。它们替代不了 BMCLAPI 在本体层的作用，只能替代 Mod 层。
5. MultiMC 慢与"官方源慢"是两件事：MultiMC 自己还经过一层 meta 服务，不等于 Mojang 文件服务器慢。

## 三、BMCLAPI 故障定位细节

请求 `https://bmclapi2.bangbang93.com/mc/game/version_manifest_v2.json`：

```
HTTP/1.1 302 Found
X-RateLimit-Limit-short: 10
X-RateLimit-Remaining-short: 8        ← 不是限流
Location: https://bmclapi21.sakura.sld.tw:443/download/f9e02be6...&e=mvggc2xw
```

- 302 是 BMCLAPI 的**正常分发机制**（把下载甩给 CDN 节点）
- 该节点 `bmclapi21.sakura.sld.tw`（日本 Sakura 机房）当前不可达
- `bmclapi.bangbang93.com`（v1 域名）实测 200 正常
- 结论：**调度中心活着、节点挂了**。PCL/HMCL 自带重试与多节点选择，所以玩家端通常感觉不到；用浏览器/curl 直连会卡死，从而误传成"BMCLAPI 崩了"

## 四、分层替代方案

### 第 1 层：游戏本体（版本 JSON / client.jar / libraries / assets）

- **主用：Mojang 官方源**（实测可用且不慢）
  - `https://launchermeta.mojang.com/mc/game/version_manifest_v2.json`
  - `https://libraries.minecraft.net/`（库文件，实测 1.36 MB/s）
  - `https://resources.download.minecraft.net/`（assets）
- **备用：BMCLAPI v1 域名** `bmclapi.bangbang93.com`
- **备用：BMCLAPI v2**（能通时速度最好，1.6 MB/s；节点抽风时换 v1）
- 启动器处理方式：把下载源在设置里从「自动/BMCLAPI」切到「官方」即可

### 第 2 层：加载器

| 加载器 | 状态 | 建议 |
|---|---|---|
| Fabric / Quilt | 正常 | 直连 `meta.fabricmc.net` |
| Forge | 正常（~119 KB/s） | 直连 `maven.minecraftforge.net` |
| **NeoForge** | **DNS 污染，直连失败** | 需代理；或用整合包内自带的 NeoForge 库；或从 CurseForge 整合包整体获取 |

### 第 3 层：Mod / 整合包

- **Modrinth**：API 直连可用（0.62s），CDN 通；启动器内可选 Modrinth 源
- **CurseForge**：网页 403（Cloudflare），但 **PCL / HMCL 内置 API Key 可正常调用**；CI 或自写脚本需自带 key
- **MCIM（mcimirror.top）**：国内 Mod 镜像，可用但慢，适合 CurseForge 抽风时兜底
- 注意：**.mrpack / CF 整合包 zip 不含游戏本体**，仍需本体层文件

### 第 4 层：Java 运行时

- `api.adoptium.net` 正常；也可用 `https://mirrors.tuna.tsinghua.edu.cn/Adoptium/`

## 五、建议动作（按优先级）

1. **不要为了"BMCLAPI 可能挂"而恐慌性迁移**——它现在文件层是 1.6 MB/s 的。
2. 启动器里把下载源设为「**官方**」做日常主用；遇到官方慢再切 BMCLAPI v1。
3. NeoForge 用户：确认能否直连；如需代理，单独为 maven 配规则。
4. **真正的未雨绸缪：把一份完整 `.minecraft` 备份成可复制资产**。
   - 备份 `versions/`（含 `client.jar`、`*.json`）、`libraries/`、`assets/`、`saves/`、`options.txt`、`mods/`、`config/`
   - 只要有一份完整目录，**任何下载源消失都不影响你继续玩**，且可换机迁移
   - 建议按版本做完整性校验（记录 json 里每个文件的 sha1）
5. 不要使用：群里流传的"改版 PCL exe"、代解封服务、来路不明的镜像（已有木马实证）。

## 六、BMCLAPI 的真实覆盖范围（官方文档 + 实测核实）

依据 `https://bmclapidoc.bangbang93.com/` 的端点清单，BMCLAPI 只镜像这些：

| 类别 | 端点 | 说明 |
|---|---|---|
| Version | `/version/*`、`/mc/game/version_manifest*.json` | MC 本体：json / client / server / libraries / assets |
| Forge | `/forge/*`、`/maven/net/minecraftforge/*` | 列表、下载（302）、maven 镜像 |
| NeoForge | `/neoforge/*`、`/neoforge/meta/*` | 列表、下载（302）、maven api 镜像 |
| OptiFine | `/optifine/*` | 列表、下载（302） |
| LiteLoader | `/liteloader/*` | 列表、下载（302） |
| Java | `/java/list`、`/java/jre_*.exe` | JRE 安装包缓存 |
| Mirrors | `/mirrors/authlib-injector` | 外置登录支持 |
| OpenBMCLAPI | `/openbmclapi/sponsor` | 志愿者节点调度与赞助 |

**明确不含：Mod 文件、整合包文件、CurseForge / Modrinth API 的代理。**

### v1 域名实测（2026-10-20）

| 端点 | 结果 |
|---|---|
| manifest | 200，277,821 B，4.71s |
| version json（1.20.1） | 200，34,974 B，2.24s |
| client.jar（1.20.1） | 200，23.0 MB，5.0s → **4.6 MB/s** |
| server.jar（1.20.1） | 200，47.8 MB，8.2s → **5.8 MB/s** |
| forge installer（1.20.1-47.2.0） | 200，5.97 MB，4.96s → 1.2 MB/s |
| forge maven metadata | **302 → 节点超时** |
| neoforge maven metadata | 200 但 20s 只收到 36 KB / 68 KB（极慢） |
| fabric-loader metadata | 404（不在镜像覆盖内，路径不同） |

即：**本体下载极强（4~6 MB/s，是 Mojang 官方 1.36 MB/s 的 3~4 倍）；maven 类路径部分节点不稳定。**

## 七、"整合包下载能力"拆解：BMCLAPI 到底管哪几步

装一个整合包的真实链路：

| # | 步骤 | 由谁提供 | BMCLAPI 停摆后 |
|---|---|---|---|
| 1 | 取整合包元数据（`.mrpack` / `manifest.json`） | CurseForge / Modrinth / FTB API | **完全不受影响** |
| 2 | 按清单逐个下载 Mod | CF CDN / Modrinth CDN | **完全不受影响**（实测 Modrinth jar 610 KB/s、mrpack 218 KB/s 均正常） |
| 3 | 下载 MC 本体（json/client/libraries/assets） | Mojang 官方 + BMCLAPI 加速 | **退化为官方源 1.36 MB/s**（能用，慢 3~4 倍） |
| 4 | 下载加载器 | Forge / NeoForge / Fabric maven | Forge 可直连（119 KB/s）；**NeoForge 直连 DNS 污染，必须代理** |
| 5 | 安装 Java（如需） | Adoptium / BMCLAPI JRE | 可直连 `api.adoptium.net` |

**结论：不是"失去整合包下载能力"，而是"一键安装退化"。**
功能上仍能装完，代价是时间（首次装大型整合包要拉几百个库文件，从几分钟变几十分钟），以及 NeoForge 系整合包在无代理时可能直接装不上。

## 八、BMCLAPI 的真实风险来源（按发生概率排序）

1. **节点抽风（已发生）**——`bmclapi21.sakura.sld.tw` 当前不可达。这是「中心调度 + CDN 节点」架构的常态，会自愈，不是崩盘。
2. **调用方断崖（本轮事件正在造成）**——PCL/HMCL 移除下载功能后不再调用 BMCLAPI，最大两个客户端消失，流量与赞助动力同步下降。这是最值得警惕的一条，且会自我实现。
3. **个人项目存续**——服务由 `bangbang93` 个人维护 + OpenBMCLAPI 志愿者节点 + 赞助商；4~6 MB/s 的带宽成本真实存在。
4. **监管范围外溢**——若"下载入口收口"扩到镜像站层面（目前无任何证据）。

对第 2 条的应对不是"找替代"，而是"**在它还在时把东西落到本地**"。
